# AZIRAL Brand Frontend

**Независимый навык AZIRAL, автор - Олжас Азирали.** Репозиторий не связан с Leonxlnx и не одобрен им. Оригинальный [Taste Skill от Leonxlnx](https://github.com/Leonxlnx/taste-skill) является отдельным проектом. Здесь опубликованы собственные инструкции AZIRAL; код, текст навыков и изображения оригинального проекта не включены.

![AZIRAL BRAND FRONTEND](assets/cover.svg)

Навык помогает превратить факты о продукте в понятный интерфейс: выбрать визуальное направление, сохранить идентичность бренда и проверить результат на разных языках и устройствах.

## Установка

В среде агента с поддержкой Agent Skills:

```bash
npx skills add azirali/taste-skill --skill aziral-brand-frontend
```

Для ручной установки скопируйте папку `skills/aziral-brand-frontend` в каталог навыков своего агента. В Codex навык вызывается как `$aziral-brand-frontend`. Внутри находятся инструкции и шаблоны; установка фреймворка или расширения браузера не требуется.

## Пример запроса

```text
Используй $aziral-brand-frontend, чтобы улучшить страницу приложения
на русском, английском и казахском. Сохрани бренд и существующие маршруты.
Сделай интерактивный первый экран удобным для касаний, сохрани обычную
прокрутку и проверь результат в браузере. Используй материалы проекта.
```

## Что получится

- Короткий бриф с проверенными фактами, содержанием, доступными материалами и действиями посетителя.
- Визуальное направление с решениями по шрифтам, отступам, цветам, изображениям и движению.
- Интерфейс с настоящими переводами и равноценными действиями для касаний и клавиатуры.
- Отчёт с размерами экранов, проверенными сценариями, скриншотами и оставшимися проблемами.

Для небольшой правки компонента сохраняется стиль окружающего интерфейса. Новое визуальное направление выбирается, когда задача действительно предусматривает редизайн.

## Совместная работа с Taste Skill

Если в среде уже есть Taste Skill от Leonxlnx, его можно использовать для арт-дирекции. Наш навык дополняет работу брифом о продукте, языковыми ограничениями, проверкой способов ввода и фиксацией результата. Применяйте подходящие инструкции и сохраняйте явные пожелания пользователя.

Пример в репозитории не является отчётом о выполненном клиентском проекте. Подтверждения проверки создаются при работе с реальным интерфейсом.

## Участие

Для полезного issue достаточно небольшого брифа или воспроизводимого сценария, ожидаемого и фактического результата. Скриншот добавляйте, если он помогает объяснить проблему. Не включайте закрытые данные клиентов. Особенно полезны улучшения языковых проверок и мобильных сценариев.
